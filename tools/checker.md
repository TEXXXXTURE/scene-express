# tools/checker.md — 交付打分自检

> 写作完成后、交付前的自检协议。按"打分循环"执行：不是硬性闸口，而是**利于循环的反馈机制**——
> 允许少量容忍，累计超阈值才重写；每轮重写把扣分原因回喂给生成。
> 依据：shared/safeguards.md（保真维）+ 模块卡校验区（场景规则维）+ shared/metrics.md（风格漂移维）。

---

## 1. 三个维度

| 维度 | 依据 | 性质 |
|---|---|---|
| 保真维 | shared/safeguards.md 四条护栏 | **零容忍**：编造来源/事实直接判不合格 |
| 场景规则维 | 模块卡"校验区"扣分项（3–5 条） | 容忍式：累计超阈值才重写 |
| 风格漂移维 | 模块卡"参数档位"对照 metrics.md 测量 | 容忍式：偏离档位即扣分 |

---

## 2. 打分流程

### 第 1 步 · 保真检查（先做，硬判定，走机器检查）

按 shared/safeguards.md §2 执行**四项机器检查**（数字一致性 / 极性 / 因果 / 引语），再辅以 LLM 判定无法穷举的语境项：

- 任一检查判**不合格**（数字未核实未标待核 / 断言反转 / 因果颠倒或新增 / 引语不符或来源缺失）→ **不合格，直接重写**（不进容忍区），原因：保真。
- 程度夸大 / 并列写成因果等扣分项 → 记入 S1 扣分。
- 推断未标注？关键歧义未确认？→ 扣分（标注位扫描 + 流程检查）。

输出保真检查报告（safeguards §2 格式），附在重写原因中回喂。

### 第 2 步 · 场景规则检查
按模块卡校验区逐条判定，每命中一条扣 1 分，累计得 S1。

### 第 3 步 · 风格漂移检查
按模块卡参数档位对照产出文本测量（metrics.md 提取法）：
- 每偏离一个档位（如卡要求"短句"产出平均 40 字）扣 1 分，累计得 S2。

### 第 4 步 · 判定与循环

```
S = S1 + S2
若 保真维不合格        → 立即重写（不消耗重试预算），原因：保真
否则若 S > 卡阈值(默认3) → 重写（消耗 1 次预算），回喂逐条扣分原因
否则                   → 通过，交付
预算用尽（默认 2 次）    → 交付当前最优版本，附残余扣分清单
```

---

## 3. 回喂格式（重写时附给生成）

```
本次扣分：
- 保真维：{保真检查报告：数字一致性/极性/因果/引语逐项结果}
- 场景规则维：{扣分项原文} ×N（{判定方式}）
- 风格漂移维：{指标} 当前{测量值}，目标{档位}
请针对以上各项修正后重写，保留其余内容不变。
```

---

## 4. 输出报告（交付时）

交付文本后附一行自检报告（可省略，用户要求时输出）：

```
自检：保真 ✓ | 场景规则 0 扣分 | 风格漂移 0 偏离 | 预算剩余 2
```

---

## 5. 说明

- 扣分项数量有上限：模块卡校验区 3–5 条，超过说明卡写得太细，先精简卡再谈校验。
- 词表扫描（lexicon 命中）是**确定性手段**，用于场景规则维；LLM 判定用于无法穷举的项（情绪、升华、人设贴合）。
- 打分是"无限调优过程"的接口：每轮重写都比上一轮更贴卡；用户对结果不满意时，先改卡，再改产出。
