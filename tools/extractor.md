# tools/extractor.md — 指标提取器

> 把用户认为"写得对"的样例文本，逆向提取成一张可执行的模块卡。
> 依据：shared/metrics.md 的 13 项指标。产出：routes/modules/ 下的新卡或对现有卡的校准。

---

## 0. 三种模式

| 模式 | 输入 | 精度 | 用途 |
|---|---|---|---|
| **精提取** | 3–5 篇同风格成品样例 | 高（跨篇取共性） | 正式建卡 |
| **粗提取** | 1 篇成品样例 | 低（单篇特征） | 快速起稿 / 临时风格 |
| **对照对提取** | AI 初稿 + 人工定稿（≥1 对） | 高（修改即信号） | 校准现有卡 / 捕捉隐性偏好 |

> 三种模式产出同一 schema 的模块卡，可混合使用：多篇成品精提取打底 + 1 对草稿/定稿对照校准。

---

## 1. 精提取工作流

### 第 1 步 · 逐篇拆解
对每篇样例，按 metrics.md 的 13 项指标逐项测量，**逐项记下原文出处**（证据链）：

| 指标 | 测量值 | 原文出处（引一句） |
|---|---|---|
| 结论位置 | 先结论 | "……"（第 1 段第 2 句） |
| 平均句长 | 12 字 | 抽样统计 |
| … | … | … |

### 第 2 步 · 跨篇浓缩
- 取**多数样例共有**的特征为稳定指标。
- 只出现在单篇的特征视为噪音，剔除。

### 第 3 步 · 数值翻译
指标值 → 行为描述（metrics.md 第 3 节）：
- "平均句长 12 字" → "短句为主"
- "情绪词密度 ≈ 0" → "零情绪"
- "人称以'我'为主" → "亲历者视角"

### 第 4 步 · 人设推断
由 语气 × 人称 × 词汇 × 结构 反推"这像谁在说话"：
- 零情绪 + 先结论 + 短句 → 克制专业的陈述者（下属 / 同事）
- 放开情绪 + 你系 + 长短交错 → 面向读者的写作者
- 术语密集 + 无主语 → 工程师 / 文档作者
- 推断结果必须能由指标指回，不凭空编人设。

### 第 5 步 · 生成模块卡草稿
按统一 schema 输出（见 §3），包含：
- 触发（由样例场景归纳）
- 人设（第 4 步推断 + 一句"为什么这么说"）
- 表达倾向（信息组织 / 取舍 / 语气 / 词汇句式，全部来自浓缩后的指标）
- 参数档位（metrics.md 档位表）
- 示例锚点（**从样例中选 1–2 段最有代表性的原文**，标注出处；不新写）
- 兜底限制（保真护栏 + 该风格必禁项 2–4 条，如样例显示"从不用'我们'"，则禁"我们"）
- 校验区（3–5 条扣分项，对应上面必禁项）

### 第 6 步 · 确认与写入
- **把草稿交给用户确认**：人设对不对、锚点选得准不准、有没有想改的档位。
- 用户确认后写入 `routes/modules/xx-xxx.md`，并在 `routes/ROUTE.md` 路由表追加一行。

### 第 7 步 · 反向验证（建议）
拿一篇**新的**同风格文本，用该卡写一段，与原文本对比：像不像、哪里不像，回改模块卡。

## 2. 对照对提取（草稿 vs 定稿）

> 核心原理：**草稿与定稿的差距 = 你的声音**（the gap is the voice）。
> 用户对 AI 初稿做的每一处修改，都是最直接的风格信号——比凭空列词表准，因为它来自真实修改行为，而不是外部推断。

### 适用输入
- 一组"AI 初稿 + 人工定稿"对照对：同一篇内容的两个版本，至少 1 对。
- 篇数越多越稳：**1 对可做快速校准，3 对以上可精修建卡**。
- 修改越"多而细"，信号越强；只有零星改动的对照对，信号弱，结论标注低置信。

### 第 1 步 · 对齐
把初稿与定稿逐句对齐，标出每处差异。逐句对不上的，按段落对齐并注明。

### 第 2 步 · 修改分类
每处差异归入类型（同一处可多类型）：

| 修改类型 | 含义 | 例 |
|---|---|---|
| 删 | 定稿删掉的内容 | 删"总而言之"式升华句 |
| 增 | 定稿新加的内容 | 首段补一句核心结论 |
| 改 | 同义改写 | "此外" → "还有" |
| 调序 | 句 / 段位置移动 | 结论从末段移到首段 |
| 拆句 / 并句 | 句长结构变化 | 长句拆成两句 |
| 换词 | 词汇替换 | "我们" → "我"、"非常" → "很" |
| 换标点 | 语气 / 节奏变化 | 句号改逗号、删感叹号 |

### 第 3 步 · 模式归纳
- 多对对照对中**反复出现**的修改 = 稳定风格信号 → 写入模块卡。
- 只出现一次的修改 = 偶然，不写。
- 被反复**删光**的内容 = 该风格必禁项 → 兜底限制 / 校验区。
- 被反复**新增或改向**的内容 = 强倾向 → 表达倾向。

### 第 4 步 · 信号翻译
修改模式 → metrics.md 指标 → 档位 / 倾向：
- 所有"我们" → "我" → 人称档：我系
- 长句全拆短 → 句长档：短
- 删光解释句（"本质上…"） → 解释腔开关：关
- 情绪词被删 / 换中性词 → 情绪档：零 / 克制
- 反复把结论提前 → 结论位置：先结论

### 第 5 步 · 生成 / 校准模块卡
- 与精提取共用同一 schema（见 §3）。
- **校准现有卡**：只更新被修改证明的段落，其余保留；在卡尾"来源样本"中标注"校准自对照对"。
- **新建卡**：按 schema 全量输出。

### 第 6 步 · 确认与写入
- 草稿交用户确认：修改归类对不对、档位对不对、有没有漏掉的修改偏好。
- 确认后写入 `routes/modules/xx-xxx.md`（新建）或就地更新（校准），同步 `routes/ROUTE.md`。

> **对照对 vs 成品样例**：成品样例只暴露"结果"，对照对暴露"过程偏好"——用户主动改了什么，权重高于静态观察。遇到"成品风格说不清哪里不对"时，用对照对最能定位。

## 3. 输出 schema（与模块卡一致）

```markdown
# 模块：{场景名}（{编号}-{slug}）
## 触发
{载体 × 对象 × 目的 的场景特征描述}
## 人设
{推断身份 + 和读者关系 + 为什么这么说}
## 表达倾向（引导）
1. 信息组织 / 2. 取舍标准 / 3. 语气基调 / 4. 词汇句式
## 参数档位
句长档 / 情绪档 / 词汇档 / 解释腔开关 / 结论位置 / 人称
## 示例锚点
> {1–2 段样例原文，标注出处}
## 兜底限制
1. 保真护栏相关 2. 该风格必禁项（2–4 条）
## 校验区（扣分项）
| # | 扣分项 | 判定方式 |
## 自检
{2–3 条交付前对照}
```

---

## 4. 粗提取（单篇快速起稿）

1. 只测 6 项高辨识指标：结论位置、平均句长、情绪词密度、人称、AI 词命中、小标题密度。
2. 直接出"一句话人设 + 三条表达倾向 + 一条示例锚点"。
3. 标注"粗提取，待用户提供更多样例后精修"。

---

## 5. 证据链纪律（强制）

- 模块卡里**每个"表达倾向 / 档位"结论必须能指回样例原文**。
- 写入方式：在模块卡末尾加一段"来源样本"（样例清单 + 每项指标的原文出处引用）。
- **对照对模式**：逐条列出关键修改对（`初稿句 → 定稿句`），结论必须能指回具体某处修改；无法指回的结论不写入。
- 无法指回原文的指标结论，不写入。
